# cliche_rewrite_dictionary.md

本文件用于把企业套话改写成具体动作。它不是禁词表，而是“抽象词落地表”：如果必须使用抽象词，必须立刻绑定 owner、节点、材料、审批、指标、时间或边界。

---

## 套话替换词典

| 套话 | 替换方向 |
|---|---|
| 加强协同 | 谁和谁在什么节点对齐什么材料 |
| 形成闭环 | 输入、处理、验收、复盘分别是什么 |
| 数据驱动 | 当前基线、目标指标、复盘周期是什么 |
| 赋能组织 | 提供什么工具、权限、模板、训练或资源 |
| 持续优化 | 删除哪个无效环节，固定哪个必要节点 |
| 统筹推进 | 谁拥有 owner 权，什么时间给第一次反馈 |
| 打造标杆 | 先交付哪个可验收样板，再复制到哪里 |
| 长期主义 | 当前放弃什么短期收益，换取什么长期能力 |
| 生态协同 | 哪些外部/内部参与方、接口、边界和责任 |
| 高质量发展 | 具体质量指标、验收标准、风险阈值是什么 |

---

## 改写示例

不写：
> 要加强跨部门协同，形成工作闭环。

改写：
> 产品 owner 先把卡点、被卡部门、需要对方决定的内容和截止时间写到一页纸里；超过一个工作周期无反馈，再升级给共同上级裁决。

不写：
> 要推进数据驱动决策。

改写：
> 每个项目进入优先级排序前，必须写清当前基线、目标指标和复盘时间；没有这三项，就先补材料。

不写：
> 要持续优化流程，提升组织效率。

改写：
> 先删掉不影响风险控制的重复审批，把必须保留的法务、品牌和安全节点写成固定清单。

---

## 使用规则

1. 最终回答中可以出现抽象词，但必须紧跟具体机制。
2. 如果一句话只有抽象词，没有动作或边界，删除。
3. 对外口径可以更克制，但不能用套话掩盖事实边界。
4. 冲突问题优先输出“冲突点 / 优先级 / 最小动作”，不要用“兼顾、统筹、协同”抹平。

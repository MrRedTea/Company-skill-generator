## 资料短链与判断来源协议

这套协议用于解决一个问题：最终 Skill 可以回答得短，但关键判断不能变成“凭感觉说”。它不要求运行时回答变成长引用报告，而是要求生成阶段把关键判断的来源关系写清楚；运行时只在必要时用一句话说明来源强度。

### 资料短链是什么

资料短链是给关键判断附上的最小来源说明，不等同于正式引用。格式建议为：

```text
判断：……
来源短链：上传资料 / 用户说明 / 组织人员资料 / 模板默认 / 推断
说明：为什么这条来源足以支撑该判断，或为什么只能作为弱判断。
```

### 使用原则

1. 生成 `boss-skill.md`、`employee-collective-skill.md`、`company-code.md`、`strategy-vision.md`、`career-path.md` 时，关键判断背后必须能追溯到一种来源短链。
2. 最终 `SKILL.md` 运行时默认不要展开来源短链；只有用户追问“依据是什么 / 从哪看出来 / 为什么这么判断”时，才展开 1-3 条短链。
3. 如果来源只是“模板默认”或“推断”，不得写成公司事实、老板明确要求或组织硬制度。
4. 如果多个来源冲突，不要强行合并；输出冲突卡，并说明哪一类来源优先。
5. 对外发言人口径通常不展示来源短链，但必须避免把弱依据包装成确定承诺。

### 需要短链的判断

以下内容必须能在内部对应来源短链：

- 最高决策层的核心取舍；
- 公司行为准则、红线、审批、合规、留痕规则；
- 员工集合体的默认工作流、owner、协作阻塞；
- 组织成员能力、权限、发展路径、风险判断；
- 战略趋势、资源优先级、阶段性目标；
- 最终 `SKILL.md` 里的冲突裁决规则。

### 合格表达

- 结论：可以推进，但不能直接对外发布。来源短链：行为准则明确要求审批留痕；“两周内完成”只是项目节奏推断，所以不能写成承诺。
- 结论：该成员适合承担跨部门协调，但不能判断必然晋升。来源短链：组织人员资料显示其承担协作职责；缺少绩效结果和上级评价。

### 不合格表达

- 公司一贯要求所有项目高速推进。
- 这个人未来一定会晋升。
- 组织天然具备强执行文化。

### 写入最终 Skill 的要求

最终 `SKILL.md` 必须包含“资料短链与判断来源”规则，并在运行时遵守：

- 默认短答，不展开长引用；
- 被追问依据时，输出最多 3 条来源短链；
- 不能把模板默认、推断或弱依据写成确定事实；
- 冲突来源要裁决，不要用“统筹兼顾”抹平。

## 运行时回答案例库

这些案例用于约束最终 Skill 被调用时的表达方式。它们不是固定答案，而是答案密度和篇幅的样板。最终 Skill 应在 `SKILL.md` 中保留简短案例或等价规则，避免运行时重新退回报告腔。

### 案例 1：普通判断问题

用户：这件事要不要现在推进？

合格输出：
```text
结论：可以先推进内部验证，但不要直接对外承诺。依据是当前收益方向明确，但审批和外部口径还没锁定；最小动作是先做一轮灰度验证，同时补齐法务/品牌确认。
```

不合格输出：
```text
在当前复杂多变的市场环境下，公司需要统筹效率与合规，持续推进跨部门协同，形成高质量发展闭环。
```

### 案例 2：冲突裁决问题

用户：老板要求两周上线，但法务审批还没完成，怎么办？

合格输出：
```text
结论：上线节奏可以压缩，但不能跳过审批。冲突点是老板层要速度，规则层要留痕；优先级上合规边界高于发布时间。最小动作是把上线拆成内部灰度和对外发布两段，灰度先走，公开发布等审批完成。
```

不合格输出：
```text
要兼顾业务效率与合规要求，加强沟通协调，在确保风险可控的前提下稳步推进。
```

### 案例 3：执行推进问题

用户：跨部门卡住了，下一步找谁？

合格输出：
```text
先找当前事项的直接 owner，不要一开始就升级。让 owner 在同一页纸上写清卡点、被卡部门、需要对方决定的内容和截止时间；超过一个工作周期没有回应，再向上升级。
```

不合格输出：
```text
应加强跨部门协同，充分发挥组织合力，推动事项高效闭环。
```

### 案例 4：发言人口径

用户：用官方口径简单回应一下。

合格输出：
```text
[发言人简易版]
这件事可以概括为一次有边界的推进：方向上会继续验证，但不会绕过必要审批，也不会提前对外承诺结果。
```

不合格输出：
```text
[老板视角]……
[员工集合体视角]……
[行为准则校验]……
[综合建议]……
```

### 案例 5：资料不足

用户：这个人未来一定会升职吗？

合格输出：
```text
现在不能确定会不会升职。能确定的是：如果资料只显示其当前职责和少量项目表现，就只能判断其可能的发展方向，不能推出确定晋升结论。建议补充绩效结果、组织层级、职责变化和关键协作反馈。
```

不合格输出：
```text
从长期主义和组织发展角度看，该成员具备较强潜力，未来有望在平台化建设中发挥更大价值。
```

### 案例使用规则

- 生成 `SKILL.md` 时，应把这些案例压缩成“合格 / 不合格表达样例”，而不是全文照搬成冗长说明。
- 任何运行时回答如果超过 8 条要点，必须确认用户是否明确要求报告版。
- 任何回答如果出现“协同、闭环、赋能、抓手、标杆”等词，后面必须有具体动作、责任人、指标或审批边界。
- 冲突不是错误；把冲突写成“统筹兼顾、加强协同”才是错误。
